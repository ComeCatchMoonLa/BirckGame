# AI 协作分工

> **结论：你定规格与测试边界，AI 写引擎/启动器/文档/1.x 玩法，你审探测与坐标。** 错了会被编译器或测试拦住的交给 AI；错了只表现为「窗口看起来不对但程序正常跑完」的，你必须手测或逐行审。

## 1. 分工

| 工作项 | 主导 | 你必须做什么 |
| --- | --- | --- |
| `TerminalInfo` / `SetConsole` 行为 | AI 写，你审 | 在 Windows Terminal 与旧 conhost 上看窗口尺寸、方块对齐、颜色 |
| 测试边界（测什么） | 你定，AI 写用例 | 确认「探测崩溃」「列映射」「88 款注册」被覆盖 |
| 架构（多进程启动器 vs 单进程 `RunXxx`） | 你已拍：0.1 多进程 | 不要在实现时改成单进程重构 |
| 游戏内容（1.x 清单） | 1.x 按 [需求.md](开发计划/Ver%201.x/需求.md) 刷题 | 手测该号能进、规则对上、Esc 能回。0.x 与 1.1～1.3 已通过；1.4～1.14 待核实 |
| CMake / 注册表 / 菜单样板 | AI | 能编过、菜单编号对上即可 |
| 文档 | AI | 抽查术语是否与代码一致；1.x 不写四件套 |

## 2. 任务粒度

- **0.x**：当前小版本 `TODO.md` 里可单独验收的一节。
- **1.x**：当前小版本 README 表里的那一组编号（不要一次做两版）。读需求 → 含糊处联网核对同名小品 → 用 0.x 引擎实现。

改完就审、就测，不攒批量。

## 3. 循环

```text
0.x：你定规格（或已拍的接口设计）
1.x：试卷即 需求.md 该号
  → AI 实现
  → 你审 diff / 手测终端
  → 对照需求；手测通过则勾 游戏清单对照
  → 不通过则打回
```

当前：0.x 原作与 1.1～1.3 已手测；1.4～1.14 待人工核实后再勾清单。
