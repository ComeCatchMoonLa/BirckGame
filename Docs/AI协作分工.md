# AI 协作分工

> **结论：你定规格与测试边界，AI 写引擎/启动器/文档，你审探测与坐标。** 错了会被编译器或测试拦住的交给 AI；错了只表现为「窗口看起来不对但程序正常跑完」的，你必须手测或逐行审。

## 1. 分工

| 工作项 | 主导 | 你必须做什么 |
| --- | --- | --- |
| `TerminalInfo` / `SetConsole` 行为 | AI 写，你审 | 在 Windows Terminal 与旧 conhost 上看窗口尺寸、方块对齐、颜色 |
| 测试边界（测什么） | 你定，AI 写用例 | 确认「探测崩溃」「列映射」「88 款注册」被覆盖 |
| 架构（多进程启动器 vs 单进程 `RunXxx`） | 你已拍：0.1 多进程 | 不要在实现时改成单进程重构 |
| 游戏内容（未实现小游戏） | 1.x | 0.x 不写玩法 |
| CMake / 注册表 / 菜单样板 | AI | 能编过、菜单编号对上即可 |
| 文档 | AI | 抽查术语是否与代码一致 |

## 2. 任务粒度

AI 单次改动 = 当前 `TODO.md` 里可单独验收的一节。改完就审、就测，不攒批量。

## 3. 循环

```text
你定规格（或已拍的接口设计）
  → AI 实现
  → 你审 diff / 手测终端
  → 对照游戏设计验收节
  → 通过则勾 TODO；不通过则打回
```
