# 掌机速度与帧率

> **结论：Brick Game 的 SPEED 是开机菜单上的全局档，开局前用 Right/Speed 选，一般 1～10（有的机 0～15）。它不是显示器刷新率。** 逻辑节拍靠 4 位 MCU 定时器，比 LCD 扫描慢一个数量级。本仓库用 `Sleep(1)` 空转，在 Windows 11 上大约 1ms 一圈，所以会快到接近屏幕刷新的观感。

## 1. 真机怎么调

| 键 | 菜单上做什么 | 游戏中做什么 |
| --- | --- | --- |
| Left / Level | 选 LEVEL | 左移 |
| Right / Speed | 选 SPEED | 右移 |
| Start | 用当前 SPEED/LEVEL 开局 | 暂停/继续 |

来源：说明书通稿（Right 在开局前选 1～10 速度）、[Retro Consoles Wiki](https://retroconsoles.fandom.com/wiki/Brick_Game)、常见 9999 in 1 模拟器 HUD（Speed max 15）。

LEVEL 多半改初始堆高/障碍；SPEED 改下落、卷轴、敌人步进的间隔。是**整机一档**，不是每款游戏自己一套键。

## 2. 真机有多慢

- 屏是 10×20 左右的 LCD 点阵，不是 GPU 帧缓冲。
- MAME 的 HT1130：LCD 扫描约 **64Hz**（多路驱动），与 OSC 无关；这是格子闪的上限，不是方块每秒掉 64 格。
- CPU 是 Holtek 4 位 MCU（HT1130 一类），逻辑走片内 8 位定时器。SPEED 1 的俄罗斯方块是「数秒掉一格」那个量级；SPEED 10 仍然是手持机节奏，不是 60/144Hz 动画。

没有「和显示器刷新率挂钩」这回事。真机没有 vysnc。

## 3. 本仓库为什么会飞

几乎所有已实现游戏都是：

```text
while (true) {
    Sleep(1);
    计数器到了才移动;
    kbhit();
}
```

| 游戏 | 节拍 | Sleep(1)≈1ms 时 |
| --- | --- | --- |
| Tetris | `t++ > 50` | 约 20 次下落/秒 |
| TetrisPro | `t++ > (30 - speed)` | 更快 |
| SnackPro | `t++ > 30 - Speed*5`，Speed 仅本游戏 1～5 | 约 40～200 步/秒 |
| Racing | 每 32 圈卷一路 | 约 30 次/秒 |
| Eliminate / FullUp | `!(t&1)` 移弹 | 约 500 次/秒 |
| 寸步难行 | `!(t&1)` 移球 | 约 500 次/秒 |

`Sleep(1)` 在老 Windows 上常被凑成 ~15.6ms；Win11 高精度计时后接近 1ms。循环里每次 `cout`，Windows Terminal 还会按显示器刷新去呈现，于是**看起来像跟刷新率绑在一起**。

本仓库没有整机 SPEED。只有贪吃蛇 Pro、俄罗斯方块 Pro 各写了本游戏速度。

## 4. 对引擎的含义（未实现）

要贴近掌机，应在引擎提供统一节拍，而不是各游戏 `Sleep(1)`：

- 开机/启动器可选 SPEED 1～10，所有游戏读同一档。
- 一档对应固定逻辑间隔（例如 SPEED 1 ≈ 400～800ms 一拍，SPEED 10 ≈ 50～80ms），与显示器 Hz 无关。
- 输入仍可每圈轮询；移动/下落/卷轴只在节拍上发生。

切片是 **0.2 掌机速度**，四件套见 [`../开发计划/Ver 0.x/0.2/`](../开发计划/Ver%200.x/0.2/)。只服务启动器选档和已实现 9 款的循环，不为未实现游戏预留第二套时钟。
