# 0.1 游戏设计：掌机壳与终端正确性

> **交付目标：玩家打开启动器能看见清单全部编号，已实现的能进，未实现的提示「未实现」；窗口尺寸、方块对齐、颜色在当前终端上正确。**
>
> 不做任何新玩法，不重写旧游戏内部循环。YuWen 已删除。

调研见 [`../../../机制研究.md`](../../../机制研究.md)、[`../../../终端与控制台调研.md`](../../../终端与控制台调研.md)。清单见 [`../../../参考/游戏清单对照.md`](../../../参考/游戏清单对照.md)。

## 1. 设计原则

- 启动器是掌机壳，不是又一个游戏。
- 终端对不对，以玩家眼睛为准：格子对得齐、窗口不是乱尺寸、底色灰字黑（`80`）。
- 旧游戏玩法保持原样；回菜单靠关掉游戏窗口（旧游戏 Game Over 会递归 `run()`，进程不自己退）。

## 2. 做 / 不做

| 做 | 不做 |
| --- | --- |
| 菜单列出清单全部，名称与游戏列表一致 | 0 号「引擎」当可玩游戏 |
| 已实现：1～7、17 进入对应增强版 | 把 Tetris 基础版也放进主菜单 |
| 未实现：提示「未实现」，留在菜单 | 为未实现项建空文件夹 |
| 游戏进程结束后回到菜单并重设窗口 | 单进程 `RunXxx()` 重构 |
| 探测终端后再设窗、设色、藏光标 | 假定一定是旧 conhost |

## 3. 流程

```text
启动 brick_launcher
  → 探测终端、设窗、画菜单
  → 输入编号
        0 → 退出启动器
        未实现 → 提示，回菜单
        已实现 → CreateProcess，等待
              → 子进程结束 → 重新设窗、画菜单
```

## 4. 菜单映射（已定）

| 输入 | 显示名 | 行为 |
| --- | --- | --- |
| 1 | 俄罗斯方块 | `TetrisPro.exe` |
| 2 | 贪吃蛇 | `SnackPro.exe` |
| 3 | 消除射击 | `Eliminate.exe` |
| 4 | 填补射击 | `FullUp.exe` |
| 5 | 淘气方块 | `NaughtyBrick.exe` |

| 17 | 迷宫 | `MazeOne.exe` |

## 5. 验收标准

- 启动器标题可读，清单全部都能看到，未实现项有「未实现」。
- 选 1、2、17 能弹出对应游戏；关游戏窗口后回到启动器菜单。
- 选 8 不启动任何 exe，菜单仍在。
- 在 Windows Terminal（或 Cursor 终端拉起的 exe）里：启动器窗口不是乱码挤成一团；方块字按双宽对齐。
- 若本机还有旧 conhost，同样能开启动器，颜色为灰底黑字或明显接近。
- 旧游戏单独运行（不经启动器）仍然只调 `SetConsole`，不再自己 `mode con`。
