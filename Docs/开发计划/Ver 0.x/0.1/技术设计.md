# 0.1 技术设计

> **技术目标：引擎能识别终端种类并按路径设窗；CMake 能编出启动器、旧游戏、单测；启动器按注册表多进程拉起已实现游戏。**

接口形状见 [`接口设计.md`](接口设计.md)。

## 1. 技术原则

- `SetConsole` / `SetPos` / `Fill*` / `Pause` 签名保持兼容，旧 `.cpp` 只改链接方式。
- 探测失败（重定向、无控制台）返回合法枚举，不抛、不 `abort`。
- 源码与文档统一 UTF-8；CMake `/utf-8` 或 `-finput-charset=UTF-8`；`SetConsole` 把控制台代码页设为 65001。

## 2. 分层

```text
brick_launcher          菜单、CreateProcess
brick_* 游戏 exe        各自 main()
        \             /
         brick_engine   Probe / SetConsole / Registry
brick_tests             doctest，只测纯函数与注册表
```

## 3. 目录与目标

| 路径 | 职责 |
| --- | --- |
| `BrickGame/Engine/Terminal.*` | 探测、列映射、resize/color |
| `BrickGame/Engine/BrickEngine.*` | 兼容 API |
| `BrickGame/Engine/GameRegistry.*` | 清单全部登记 |
| `BrickGame/Launcher/Main.cpp` | 启动器 |
| `tests/third_party/doctest.h` | 已点名的测试框架 |
| `CMakeLists.txt` | `brick_engine`、各游戏、`brick_launcher`、`brick_tests` |

运行时输出到 `build/bin/`，保证启动器与游戏 exe 同目录。

CMake 游戏目标：`Tetris`、`TetrisPro`、`Snack`、`SnackPro`、`Eliminate`、`FullUp`、`NaughtyBrick`、`CantMove`、`Racing`、`MazeOne`、`MazeRoot`。`Can't Move` 路径用引号。

## 4. 进程模型

启动器 `CreateProcessW(conhost.exe, ...)`（路径 UTF-16），工作目录 = 启动器所在目录，`WaitForSingleObject` 无限等。不重定向子进程 stdio。子进程结束后再 `SetConsole` 一次并重画。游戏窗口禁止拉伸。

找不到 exe：菜单提示错误，不崩溃。
