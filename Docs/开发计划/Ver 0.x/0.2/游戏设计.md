# 0.2 游戏设计大纲：掌机速度

> **草稿。** 进入 0.2 时对照引擎实际 API 再写技术设计 / 接口设计 / TODO。调研见 [`../../../参考/掌机速度与帧率.md`](../../../参考/掌机速度与帧率.md)。

## 交付目标

启动器在开局前能选整机 **SPEED 1～10**；已实现的 9 款按这一档走逻辑节拍，不再跟显示器刷新率飞。

## 消费者（只服务这些）

- 启动器：选档、把档传给游戏（或写进进程能读到的整机状态）。
- 已实现 9 款里的 `Sleep(1)` + 计数器循环。

不为未实现项设计第二套节拍，不为将来的「每游戏独立曲线」做配置表。

## 做 / 不做

| 做 | 不做 |
| --- | --- |
| 整机一档 SPEED 1～10 | 整机 LEVEL（现有游戏没有 Level 消费者） |
| 引擎提供读当前档 / 等到下一拍 | vysnc、帧插值、独立渲染线程 |
| 已实现游戏改用引擎节拍，SPEED 1 明显慢于 10 | 节拍曲线编辑器、插件式时钟 |
| 输入仍可高频轮询；移动/下落/卷轴只在节拍上发生 | 为未实现游戏预留 `ITickable` 之类空接口 |

贪吃蛇 Pro 局内 1～5 的 Speed：进入 0.2 时二选一（映射到整机档，或本版先忽略局内键），不要做两套速度再加同步层。

## 验收（进入 0.2 时写成可勾项）

- SPEED 1 的方块/蛇肉眼慢于 SPEED 10。
- 节拍不随显示器 Hz 变。
- 未改玩法规则（碰撞、计分、地图仍是旧逻辑）。
