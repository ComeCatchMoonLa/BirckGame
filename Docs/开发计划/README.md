# 开发计划

> **本文件夹是按版本推进的唯一入口。** 一个小版本 = 一条能独立验收的边界。只为最近一两个小版本写全套文档。
>
> **0.x 主要完善引擎。** 未实现玩法放到 1.x。新引擎能力必须有当前消费者（启动器或已实现的 9 款），没有第二处调用的接口不要先抽。

规则事实以 [`../机制研究.md`](../机制研究.md)、[`../终端与控制台调研.md`](../终端与控制台调研.md)、[`../参考/游戏清单对照.md`](../参考/游戏清单对照.md)、[`../参考/掌机速度与帧率.md`](../参考/掌机速度与帧率.md) 为准。

## 1. 版本号

两段式 `主.次`，不做补丁号。

| 版本段 | 含义 |
| --- | --- |
| **0.1** | 终端探测 + 启动器 + 旧游戏进菜单（壳） |
| **0.2～0.x** | 引擎底层：有明确消费者才开切片 |
| **1.x** | 按清单补未实现游戏 |
| **1.0** | 清单全部均可从菜单进入 |

小版本完成：该版 TODO 勾完、验收满足、单测绿。

## 2. 细化深度

只给**下一个**和**下下个**写全套。更远的只在路线图留一行。当前：0.1 四件套已在；0.2 / 0.3 只写游戏设计大纲。进入该版再补技术设计 / 接口设计 / TODO。

## 3. 路线总览

```text
0.1 引擎探测 + 启动器 + 旧游戏进菜单     <- 壳
0.2 掌机速度                               <- 下一刀，仅大纲
0.3 硬编码优化                             <- 下下个，仅大纲
0.4～0.x 其它引擎债（有消费者才开，不预列）
1.x 按清单补未实现游戏（青蛙过河起）
1.0 清单全部均可进入
```

0.4 不预先拆「双缓冲 / 插件 / 关卡脚本」。等启动器或某款已实现游戏真的卡住再开。
